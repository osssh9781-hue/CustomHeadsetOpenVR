# KNOWN LIMITATIONS — Mecha Lab 0.18.0

## 0.24.77
- 지브러시 화면의 각진 셰이딩은 "Sharp 엣지에 붙은 면을 평면으로" 보여 주는 방식 — 각진 엣지 옆이 곡면이면(원통 옆면 등) 그 첫 줄 면은 각지게(평면으로) 보임. 블렌더 메뉴(Mode 메뉴 등)로 직접 조각 모드에 들어가면 적용 안 됨(MECHA LAB 카드 · Tab · 지브러시 선반 동작으로 들어갈 때만). 지브러시 화면에 있는 동안 저장하면 파일 안에는 평면 상태로 저장되고, 다시 열어 오브젝트 모드로 나오면 원래대로 돌아옴.

## 0.24.76
- Fix Mesh: 큰 구멍(엣지 12개 넘고 둘레가 부품 크기의 5% 넘음)은 일부러 안 메움(열린 판의 경계일 수 있어서) — Close All Holes로. 보내주신 FBX 22개 중 4개는 면 4개가 붙은 엣지 1개가 남음(구멍을 메운 면이 옆 면과 겹친 곳). 안쪽 벽은 "벽 조각에서 쏜 광선이 홀수 번 나가면 안쪽"으로 판단 — 얇은 판이 겹친 곳은 잘못 볼 수 있음.
- 예전 Make Quad(Patch)는 고친 뒤에도 목표 면 수를 크게 넘기고(4,000 → 16,000 ~ 27,000) 열린 엣지가 남는 경우가 있음(보내주신 부품 2개에서 20 / 120개) — 새 Quad Remesh 권장.
- Export Quad Mesh: 오브젝트당 약 1 ~ 30초(작은 부품 1.5초, 수만 면 부품 20 ~ 30초) — 1,500개면 한 시간 넘게 걸릴 수 있음. 쉐이프 키가 있는 오브젝트는 그대로 내보냄. Client Look은 면이 4배(Subdivide 1).
- 꺾인 면 자르기 Limit: 보는 방향 기준이라 비스듬히 보고 자르면 정면으로 보이는 면 쪽이 기준(그 면은 전체 깊이, 나머지는 얕게).
- 지브러시 Q 선택 모드의 G / R / S는 블렌더 조각 모드의 Move / Rotate / Scale 도구(SubTool 전체를 움직임).
- 고른 SubTool 표시는 외곽선이 아니라 다른 오브젝트를 흐리게(블렌더 Fade Inactive Geometry, 50%) — 블렌더가 조각 모드에서는 조각 중인 오브젝트에 외곽선을 그리지 않아서. 지브러시 화면에 있는 동안 오버레이에서 직접 끄면 그 동안은 꺼진 채(나가면 들어오기 전 설정으로).
- 펜 우클릭: 누르고 0.25초 안에 60px 안쪽 움직임은 클릭으로 봄 — 펜으로 빠르게 짧게 끌어서 화면을 돌리려 하면 메뉴가 나올 수 있음(조금 더 누르고 있다가 끌면 회전). 실제 펜(Wacom / Windows Ink)에서 옆 버튼이 블렌더에 어떤 신호로 오는지는 확인 못 함 — 그래도 안 되면 펜 드라이버의 옆 버튼 설정이 "오른쪽 클릭"인지 확인 필요.
- Emulate 3 Button Mouse가 켜져 있으면 Alt+클릭은 블렌더가 먼저 가운데 클릭으로 바꿔서 애드온이 Alt를 볼 방법이 없음 — Alt 빼기 · Zsub · Alt+클릭 SubTool 고르기를 쓰려면 이 설정을 꺼야 함(애드온은 경고만, 블렌더 설정은 안 바꿈). 켜 둔 동안은 진짜 가운데 버튼 클릭도 메뉴를 안 엶(우클릭 메뉴는 그대로).
- Re-make Quad: 쿼드 결과를 바꾼 뒤(컷 등) 다시 만들 때마다 바뀐 메시가 숨은 `…_Changed` 오브젝트로 하나씩 남음(파일 크기 증가, 필요 없으면 지워도 됨). 바뀌었는지는 점 위치 지문으로 판단 — 수정자만 추가한 경우(라이브 불린 등)는 안 바뀐 것으로 보고 원본에서 다시 만듦(수정자는 그대로 남아서 다시 적용됨).
- 꺾인 면 자르기는 쿼드 리메시한 곡면(베벨 모서리 · 둥근 면처럼 조금씩 다른 면이 많은 곳)에서는 예전 방식(촘촘한 바닥)으로 넘어감 — "면 3개 이상이 만나는 모서리" · 조각 48개 초과 등. 평평한 윗면 안쪽만 자르면 새 방식(같은 부품에서 확인).
- Silhouette Move는 Path Move의 Whole과 같은 계산 — 부품을 잡은 곳에서 끄는 첫 방향에 수직으로 잘라야 해서, 표면에서 곧장 바깥(면과 같은 방향)으로 끌기 시작하면 "no closed section"으로 안 됨(부품 길이 방향으로 끌기 시작해야 함). 아이콘은 새로 그렸지만 실제 화면 모습은 미확인.
- "0.24.71에서는 되던 홀(Path Move Whole · 스케치 Alt 구멍 · 컷 관통 구멍)이 지금 안 됨": 화면 없는 시험에서는 0.24.71 · 0.24.75 · 0.24.76 결과가 같음 — 화면에서 키 · 마우스를 받는 쪽 문제로 보이며 원인 미확정(Emulate 3 Button Mouse는 꺼져 있다고 확인됨 — 원인 미확정. 메뉴가 뜨면 상태 줄에 "Mecha Menu (무엇)"이 나오니 그 글자를 알려 주세요).
- 무작위 크래시 테스트에서 찾은 예전부터의 문제 2개(0.24.75 코드로도 똑같이 재현 — 이번 수정과 무관): ① 지브러시 High Poly(34만 면 복사본) → Hard Edges 설정 → Ctrl+Z에서 창 없는 bpy가 죽음(시드 282; 실제 블렌더 화면에서도 나는지는 미확인 — 0.24.73에 적은 "같은 되돌리기 단계 연속 + Ctrl+Z" 크래시와 같은 종류로 보임). ② 데시메이트한 10만 면 부품에서 Hard Edges Find Edges가 약 12분(0.24.75: 717초) — 30만 면 제한 안이라 막지 않음, 먼저 더 줄이거나 Quad Remesh 권장.
- 꺾인 면 자르기 Ramp Soft: 옆 띠의 선은 윤곽선 변을 따라감 — 볼록한 모서리 근처(띠가 두 변에 다 걸리는 곳)는 가로줄 위의 점만으로 채워 조금 덜 매끄러울 수 있음.

## 0.24.75
- Quad Remesh(가벼운 부품): 쿼드 크기는 부품 전체에서 하나 — 넓은 평면도 작은 쿼드, 쿼드 한 칸보다 좁은 띠 · 홈은 엣지 하나가 끊기거나(평균 엣지 길이의 2.4%) 2배 · 4배 촘촘하게 다시 해서 면 수가 Target보다 많아질 수 있음(99개 중 16개). 넓은 곳은 큰 쿼드 · 좁은 곳은 작은 쿼드(적응형)는 아직 없음.
- 쿼드 한 칸보다 얇은 벽은 두 면이 한 엣지에 붙어 버릴 수 있음(99개 중 3개, 4면 엣지 1~3개 — 메시지에 "left open / pinched"). Target을 올리면 나아짐.
- 마스크 · 점 색은 가장 가까운 원래 점의 값(가벼운 부품은 점이 적어서 경계가 그 점 간격만큼 움직일 수 있음). UV는 예전처럼 없어짐.
- 가벼운 부품 판정은 "원하는 면 수의 20배 이하 삼각형" — 3만 삼각형 DynaMesh에 Target 5,000처럼 촘촘하지만 기준 안인 입력도 새 방식(결과는 비슷, 0.3초쯤 더 걸림).

## 0.24.74
- Match Original은 원본의 둥근 정도를 엣지 옆 평면이 만나는 모서리와 원본 표면 사이 거리로 잽니다 — 시험 블록에서 실제 반지름의 약 0.5 ~ 0.8배로 읽힘(조금 얇게). 얕게 꺾인 엣지(60° 미만)는 일부러 더 얇게 읽음(잡음이 커져서). 원본이 챔퍼(평평하게 깎음)면 둥근 베벨로 바뀜.
- Match Original에서 원본이 크게 둥근 몇몇 엣지가 Width의 10배 이상이 되면 Bevel 수정자 Width도 그만큼 커지고 나머지 엣지는 가중치로 얇게 들어감 — Width 슬라이더는 "가장 얇은 베벨"이고 실제 수정자 Width와 다를 수 있음.
- Auto Detail의 Tolerance는 원본 점의 99%가 들어와야 하는 거리 — 원본 점의 1%보다 작은 디테일(작은 볼트 하나)은 사라져도 멈추지 않을 수 있음. 그럴 땐 Tolerance를 줄이거나 Auto를 끄고 Detail을 직접.
- 원본의 넓은 챔퍼 띠(로봇 머리 부품처럼 45°로 넓게 깎인 면)는 단계적 데시메이트가 얕은 면 여러 개로 나눠 각진 엣지(30° 넘게 꺾임)로 잡히지 않고 부드럽게 나올 수 있음 — Hard Edges Angle을 낮추거나 Tolerance를 줄이면 나아질 수 있음(시험 안 함; Match Original과는 별개, 0.24.73부터).
- n각형을 단순 분할한 원본(얇은 삼각형이 많은 메쉬)에서 "고른 삼각형" 단계가 막히면 그 단계만 보통 데시메이트로 넘어감(전에는 목표보다 50% 많은 데서 멈췄음).

## 0.24.73
- Edge Mesh: 베벨 폭보다 작은 디테일(좁은 홈 · 작은 계단)은 자동으로 얇은 베벨이 들어가서, 두꺼운 Width에서도 그 부분은 덜 둥글어짐(둥근 반지름이 디테일보다 클 수 없음). 안쪽으로 꺾인 계단 모서리에 아주 작은 턱이 남을 수 있음.
- Edge Mesh는 새 토폴로지라 UV · 점 색 · 폴리그룹은 따라오지 않음(재질 번호만). 원본은 Apply / Clear 전까지 파일 안에 보관(파일 크기 증가).
- 베벨 겹침 시험 실행은 3만 면 이하에서만 — 더 큰 메쉬(Find Edges 결과 등)는 예전처럼 Blender Clamp(가장 좁은 곳에 맞춰 전체가 얇아질 수 있음).
- Find Edges + Merge Flats(2만 삼각형 이상)는 빠른 경로에서 점 속성 · UV를 버림(재질은 유지).
- 같은 되돌리기 단계가 3개 연속 + Ctrl+Z 크래시는 창 없는 bpy 빌드에서만 재현 — add-on은 그런 단계를 만들지 않게 했지만, GUI 블렌더에서도 같은 버그가 있는지는 미확인.
- Multires Divide 메모리 예측(면당 20KB)은 bpy 빌드 실측의 절반 — GUI 블렌더 실측은 아직 없음.

## 0.24.66
- Fast Decimate 엔진은 Windows x64 / Linux x64만(그 밖은 블렌더 Decimate). 점 속성(색 · 마스크)은 남은 점의 값을 그대로 가져서, 색 경계가 면 하나 정도 움직일 수 있음. UV는 이음새에서 대략, 모서리 데이터(크리스 · 심 · sharp edge)는 사라짐. Shape Key · Multires가 있으면 하지 않음.
- 크래쉬 "그 순간"의 저장은 불가능 — 마지막 사본(쉼 / 위험 작업 직전 / 간격) 뒤의 작업은 잃을 수 있음. 아주 짧은 획(0.5초 미만)은 Mecha Lab 지브러시 화면 밖(블렌더 기본 조각)에서는 못 볼 수 있음. 저장하는 동안(큰 파일 1~3초) 블렌더가 잠깐 멈춤 — 그래서 쉴 때만.
- 블렌더 조각 엔진 자체(붓 계산 · 화면 그리기)는 add-on이 바꿀 수 없음 — 하이폴 붓 속도는 블렌더 몫.

- 텍스쳐 스탬프 · DynaMesh(창 경로) · 마스크 올가미는 창 없이 시험할 수 없는 Blender 조각 연산자를 써서 미검증.

## 0.24.57
- Attach Ends: 평평한 Base Mesh를 시선 방향으로 휘는 방식 — 두 끝의 표면 방향(기울기)까지 맞추지는 않음. 끝이 메시 위에 없으면 그 끝은 원래 평면 깊이.
- 그룹 안 래디얼 부품: 래디얼 중심은 씬에 하나라서, 그룹 밖에도 래디얼 부품이 있으면 중심이 그룹을 따라가지 않음.
- test_v0243에서 드물게 Blender 충돌(segfault, 헤드리스) — 재현률 낮음, 원인 미확인.

## 0.24.56
- Live Last Cut: 다음 컷(또는 램프)까지 컷 전 메시 사본이 파일에 남음(가짜 사용자). 대상이 둘 이상이거나 Split / Ramp일 때는 라이브가 아님.
- 미러 따라가기: 부품을 찾는 기준은 새 부품 중심이 들어 있는 미러 부품의 박스 — 겹친 부품이 여럿이면 가장 작은 것.
- 그룹 Grid 간격은 Grid를 켜거나 값을 바꿀 때의 그룹 크기로 정해짐(나중에 부품 크기를 바꾸면 간격은 그대로, Gap − / +로 다시 맞춤).

## 0.24.54
- 3D 마우스 문제는 원인을 추정해 고쳤지만 실제 기기로 확인하지 못했음.
- Extend Brush: 잡은 면과 비슷한 방향(60° 안)의 면만 패치에 들어감 — 모서리를 걸쳐 잡으면 한쪽 면만 뽑힘. 패치 테두리가 한 고리가 아니면 예전 단면 방식으로 바뀜.
- Separate Tube는 여전히 단면 전체를 씀.

## 0.24.53
- Ramp: Base Mesh 램프는 Edge 폭이 깊이를 따라가서 Depth를 바꾸면 바닥 배치를 다시 만듦(깊은 쪽 변경만 빨라짐). Cut Ramp는 폭이 고정이라 Depth 변경도 재사용될 수 있음.
- 램프 뒤 편집이 감지되면 램프는 확정되고 더 이상 < > / 슬라이더로 바뀌지 않음(편집을 지키기 위해).
- 그룹 Repetition Cursor 중심은 고를 때의 커서 위치에 고정(나중에 커서를 옮겨도 그대로).

## 0.24.52
- 파트 대칭의 Radial 중심 / Count / 축은 씬 전체에 하나(Point Radial Symmetry와 같은 것) — 파트마다 다른 Count는 그룹 Repetition으로.
- Kaleido 파트에 Alt+X를 쓰면 미러 평면은 래디얼 중심을 지남(한 원점). 다른 중심이 필요하면 Mirror만 쓰거나 그룹 Repetition.
- 그룹 Repetition 복사본은 Geometry Nodes 인스턴스라 Apply 전에는 Cut / Split 대상이 아님.
- Symmetry 카드는 MECHA LAB 워크스페이스에서만, 선택된 활성 파트 옆에 뜸.

## 0.24.51
- 휠 클릭 메뉴: 휠 드래그를 처음 몇 픽셀은 애드온이 받고 그다음 Blender 회전을 시작함 — 회전 느낌이 달라지면 Preferences > Middle Click = Mecha Menu 끄기. Blender 설정에서 휠을 회전이 아닌 다른 동작으로 바꿨다면 드래그는 항상 회전이 됨.

## 0.24.50 Mecha Menu
- GPU로 직접 그려서 이 개발 환경(GPU 없음)에서는 실제 모습을 확인하지 못함. 문제가 있으면 Preferences > Classic RMB Popup으로 예전 패널.
- Blender 사이드바 / 헤더 / 메뉴는 애드온이 모양을 바꿀 수 없음(테마 색만 가능).
- Ctrl + Alt를 0.25초 이상 누르면 메뉴가 떠서, 그 상태로 Ctrl+Alt가 필요한 Blender 단축키는 막힘(빨리 누르면 괜찮음). 끄기: Preferences > Hold Ctrl + Alt.
- 슬라이더 클릭 값 입력은 메뉴를 닫고 작은 입력창을 엶(홀드 모드에서는 입력 없음).

## 0.24.49 UI
- Blender 패널 버튼 안 아이콘은 크기를 키울 수 없어 Modeler보다 아이콘이 작음(툴팁으로 이름 확인).
- Quick HUD는 실제 화면에서 위치·겹침을 확인하지 못함. 손잡이로 옮긴 위치는 Blender를 닫으면 초기화됨.
- Select / Move에서 RMB가 Blender 오브젝트 메뉴 대신 팝업을 엶(MECHA LAB 안). 원래대로: Preferences > RMB Actions Menu 끄기.
- 수정키 동작 자체는 통일하지 않음(손 기억 유지) — 화면 안내만 추가.

## 0.24.48 Quad Remesh
- 닫힌 부품만 됨(열린 메쉬는 거부).
- Flow: 컷이 남긴 가는 조각 주변에서 쿼드가 꼬이고 모서리를 놓칠 수 있음(경고는 뜸). 큰 메쉬는 수 초~수십 초 동안 멈춘 듯 보임.
- Patch: 평평한 면 조각만 고른 격자가 됨. 외곽 가까이에는 불규칙한 사각형 띠가 생김. 곡면 부분은 원래 면을 사각형으로 쪼갤 뿐이라 면 흐름이 정리되지 않음(곡면은 Flow 권장).
- UV / 재질 번호 / 속성은 옮겨지지 않음(재질 슬롯만 복사).

## 0.24.47 Ramp Resolution
- 해상도를 올리면 다시 팔 때마다 몇 초 걸릴 수 있음(슬라이더를 움직이는 동안 반응이 느림). 크고 기울어진 모양은 점 수 상한에 걸려 더 이상 촘촘해지지 않음.

## 0.24.46 Cut Ramp
- 실제 화면에서 써 보지 않음. Through All 모드여도 Cut Depth만큼 팜. Split · 반전(Alt) · Live 컷에는 Ramp 없음.
- 둥근 면 위의 바닥 깊이는 그 자리 표면 방향 기준이라 베벨 위에서는 조금 들쭉날쭉할 수 있음(조각은 안 남음).

## 0.24.45 Ramp live
- Pick Edge 클릭 · 변 표시는 실제 화면에서 확인 안 함.
- live 상태에서 Ctrl+Z를 쓰면 메쉬만 돌아가고 live 기록은 어긋날 수 있음(◀ ▶ / Remove 권장).
- 한 번에 하나만 live. 여러 대상에 걸친 Ramp(대상 2개 이상)는 live가 아님.
- Profile(Flat / Chamfer / Bevel)을 바꾸는 것은 자동으로 다시 파지 않음(◀ ▶를 한 번 누르면 반영).

## 0.24.44 Alt: Ramp
- 실제 화면에서 써 보지 않음. Free Draw로 그리면 "처음 변" = 처음 두 점(2px 이상)이라 짧은 시작 획이 방향을 정함 — 다각형 클릭이 정확함.
- Soft를 많이 올리면 얕은 쪽 절반이 거의 표면 높이라 파인 부분이 작아 보임(Carve Depth를 올리면 됨).
- Path Move: 작은 브러시로 큰 판을 Extend하면 다시 판 단면 전체가 늘어남(자동 Stretch 전환은 크래시로 제거).

## 0.24.43
- 실제 화면에서 써 보지 않음.
- Edge Finish 밖으로 나간 점을 표면으로 되돌리는 처리는 그 자리 베벨 모양을 조금 납작하게 만들 수 있음(GN Edge 권장).
- 0.24.41~0.24.42에서 GN Edge로 자른 오브젝트에는 남은 컷 표시 속성이 그대로 있을 수 있음: 다음 컷 전에 그 오브젝트의 `mch_cutter_face` 속성을 지우거나 이 버전에서 한 번 Edge Finish 없이 자르면 정리됨.

## 0.24.42 Armor Plate Alt 파기
- 실제 화면에서 써 보지 않음.
- Through 모드 · Mech Ridge 프로파일은 반전 파기 없음(Mech Ridge는 Chamfer로 팜).
- 많이 휜 표면에서는 뒤집은 모양이 조금 일그러질 수 있음(가장 가까운 표면 기준 대칭).
- Path Move: 단면이 브러시보다 크면 Stretch로 바뀌어 Extend의 깨끗한 단면 쓸기는 안 됨(브러시를 키우면 Extend). 경로를 펴는 만큼 급한 꺾임은 둥글게 바뀜.

## 0.24.41 GN Edge
- 실제 화면에서 써 보지 않음.
- 베벨 둥근 모양은 컷 벽이 표면과 직각일 때 가장 정확(비스듬한 벽은 타원 호).
- 그은 모양의 뾰족한 모서리에서는 스윕이 겹쳐 모양이 덜 깔끔할 수 있음. 면 수가 기존 Edge Finish보다 늘어남.
- Live(Auto Apply OFF) 컷에는 적용 안 됨.
- 나사 둘레 평면: 메쉬 가장자리라 둘레가 5곳 미만으로 맞으면 클릭한 면 방향 그대로.

## 0.24.40 Path Move Hardness
- 실제 화면에서 써 보지 않음.
- 부드러운 휨이 끝나는 곳 바깥쪽에 작은 단차가 살짝 보일 수 있음(경로 점 간격 때문).
- 일자로 곧게 끌면 Hardness 차이가 없음(꺾일 때만 둥글어짐). Move처럼 주변 표면을 끌어당기는 방식은 아님.
- 프리미티브 Remember Turn: 표면이 바뀔 때 표면 법선 둘레의 기준 방향은 최소 회전으로 정해져서, 아주 다른 방향의 면으로 옮기면 법선 둘레 돌림이 예상과 조금 다를 수 있음.
- Stamp Face: 휜 면(구 · 원통 옆)을 찍으면 그 점의 면 방향 기준, Stamp Depth 0이어도 겹침 방지로 1%는 들어감.

## 0.24.39 Alt 파기
- 실제 화면에서 써 보지 않음.
- Resolution을 아주 높이면 라인 끝 둥근 마개에서 표면과 만나는 곳에 아주 작은(눈에 안 보이는) 삼각형이 몇 개 생길 수 있음.
- 라이브 Base Mesh 위에 Alt로 판 홈은 슬라이더로 그 Base Mesh를 다시 만들면 사라짐(Apply 후 파기 권장).

## 0.24.38 표면 따라 파기
- 실제 화면에서 써 보지 않음.
- 표면 위 점 개수 = Resolution(15~60): 아주 큰 모양 + 많이 굽은 면이면 바닥이 살짝 각질 수 있음(Resolution을 올리면 매끈해짐).
- 메쉬 가장자리를 넘어가는 부분(표면이 없는 곳)은 가장 가까운 표면에 붙어서 모양이 늘어날 수 있음.

## 0.24.37 Invert / Alt 파기
- 실제 화면에서 써 보지 않음.
- Base Mesh Alt Carve Height는 Dome / Cushion 프로파일에서는 안내만(평평한 면이 없어서). 파는 깊이는 Height − 1 %(입구가 표면과 겹치지 않게).
- Surface Draw 홈은 Boolean(Exact)이라 큰 메쉬에서 느릴 수 있음. 홈은 그 자리에서 바로 적용(라이브 아님, Ctrl+Z로 되돌림).
- Invert는 만들 때만: 이미 만든 Base Mesh를 Invert로 뒤집지는 않음.
- ZBrush-safe Faces는 n-gon만 삼각형으로 나눔: ZBrush에서 다시 가져오면 그 삼각형들이 그대로 옴(원래 n-gon으로 합쳐지지 않음). 실제 ZBrush에서 열어 보는 확인은 미검증.

## 0.24.36 컷 깊이 / Slow Line
- 실제 화면에서 써 보지 않음.
- From Surface 2점 직선 컷은 Boolean이라 Through All의 평면 컷보다 느림.
- Slow Line은 누르고 끌며 그릴 때만(Free Draw 모양, Line 선, Path Move 길): Lasso처럼 점을 클릭해 찍는 방식에는 적용 안 됨. Mask 브러시는 제외.
- Shift 직선은 화면 기준 0 / 45 / 90°(3D 축 기준 아님). Path Move 길에는 Shift 스냅 없음.

## 0.24.35 Knife Mesh / Ctrl+Z 크기 유지
- 실제 화면에서 써 보지 않음.
- Knife Mesh는 오브젝트 자기 축(X / Y / Z) 방향으로만 자름: 비스듬히 돌아간 메쉬(메쉬 데이터 자체가 기울어진 경우)는 슬라이스도 그 축 기준. 면이 많이 늘어나니(Cuts 12 큐브 ≈ 864면) 큰 메쉬는 Cuts를 낮게.
- Ctrl+Z가 크기를 되돌리지 않으므로, 크기를 실수로 바꿨으면 F / 슬라이더로 다시 맞춰야 함.

## 0.24.34 대상 선택 / Scarf Cape
- 실제 화면에서 써 보지 않음.
- 대상 선택은 Cut과 같은 설정 하나: Cut에서 Selected Only로 두면 다른 그리기 툴도 Selected Only.
- 버튼으로 동작하는 툴(Perforate, Boolean, Mirror, Radial 등)은 원래 선택한 메쉬에만 작동해서 줄이 없음. Through All / From Surface · Auto Apply는 Cut · Split에만.
- 툴 안에서는 F가 브러시 크기라 Select / Move로 가려면 Q(또는 Esc)를 씀. 원 미리보기는 마우스 아래 표면 기준 크기(표면이 없으면 3D 커서 깊이).
- Scarf Cape는 선을 왼쪽↔오른쪽으로 그어야 함(거의 세로로 그으면 안내만 나옴). 크게 구불거리는 선은 윗단이 화면 가로 기준으로 정리됨.
- 마지막 렌더 이후 주름 높이 · 가장자리 페이드를 바꿈: 새 모양은 렌더로 확인하지 않음(자동 테스트만).

## 0.24.33 Path Move 방식 / Perforate / Surface Draw / Radial Symmetry
- 실제 화면에서 써 보지 않음: 모든 새 기능의 조작감 · 속도 미검증.
- Path Move Separate Tube: 시작 부분이 원래 메쉬와 겹치는 곳에 어두운 띠가 보일 수 있음(Merge Union 하면 사라짐).
- Path Move Extend: 잡은 곳의 단면이 닫힌 루프로 잘리지 않는 메쉬(또는 라이브 오브젝트)에서는 Separate Tube로 대신 만듦(경고 표시).
- Perforate: Exact Boolean이라 면이 많은 메쉬 + 작은 구멍이면 느릴 수 있음(Solver = Fast 선택 가능).
- Surface Draw Alt 컷: 자른 영역은 그릴 때의 화면 시점으로 고정됨(나중에 시점을 돌려도 같은 자리).
- Radial Symmetry: 복사본은 Array 모디파이어라 Apply 전까지 실제 메쉬가 아님.

## 0.24.32 Path Move / 무브 패널 옵션
- 실제 화면에서 써 보지 않음: 드래그 느낌, 미리보기 속도 미검증. 0.24.31 항목 중 Jungle Gym 내용은 툴을 지웠으므로 해당 없음.
- 잡은 부분이 단단하게 따라가는 방식이라(Hardness 높을수록 단면 유지) 아주 급하게 꺾으면 꺾인 안쪽 면이 겹칠 수 있음.
- 경로는 최대 48 스텝으로 나눔: 아주 긴 경로는 스텝 간격이 넓어져 몸통이 조금 울퉁불퉁할 수 있음.
- Through All은 오브젝트 상자(바운딩 박스)로 대상을 고름: 브러시 근처에 상자만 걸쳐도 대상에 들어가지만, 실제로 브러시 밖 점은 안 움직임.
- Auto Apply 끔은 무브 전 메쉬를 숨은 메쉬 데이터로 하나 더 저장함(파일 크기 늘어남). Apply나 Clear하면 지워짐.
- 놓을 때 스텝마다 면을 새로 만들어서, 큰 메쉬 + 긴 경로는 몇 초 걸릴 수 있음.

## 0.24.31 Concept Move / Jungle Gym
- 실제 화면에서 한 번도 써 보지 않음: 드래그 손맛, 브러시 원, 격자 · 주황 막대 표시, D 홀드, F 크기, 3D 마우스(Follow View) 모두 미검증.
- Jungle Gym 격자를 마우스만 올려도 보이게 하는 부분(툴 키맵 MOUSEMOVE)이 Blender에서 동작하는지 확신 없음. 안 되면 드래그 중에만 보임.

  있는 원인(등록 중단 B09, 도구 목록에서의 툴 전환 실패, 미확정 Fuse 미리보기의 패널 점유, Undo 후 남은 상태)을 고친 것이며
  실제 원인과 같다고 단정할 수 없습니다. 아직 문제가 있으면 **Workspace & Hotkeys > Run Mecha Lab Self Test** 결과(클립보드에
  복사됨)와 Blender 시스템 콘솔 로그를 보내 주세요.
- Alt+짧은 클릭 판정: 0.5초 이내, 5px×UI Scale 이내 이동. Object Mode의 Alt+클릭 복귀는 Blender의 `CLICK` 이벤트 사용
  (Blender 기본 Alt+클릭 = 오브젝트 목록 선택은, 오브젝트가 없는 곳에서는 그대로 동작).
- 직선 Cut의 "남길 쪽 클릭"은 Alt+클릭에서 **Ctrl+클릭**으로 바뀜(Alt+클릭은 도구 종료).
- Base Mesh Alt+드래그 커터: Flat/Chamfer/Bevel만(Dome은 거부). 깊이 = Height, 표면 바로 위 1% 높이에서 시작(동일 평면 회피).
  대상은 선택된 메쉬(Live Base Mesh 제외), 없으면 도형 중심 아래 메쉬.
- Base Mesh 세션 Auto Apply = Live 해제(Freeze)이며 형상은 그대로. "세션"은 마지막으로 도구를 떠난 뒤 만든 Base Mesh.
- Stabilizer: 드로잉 중 60Hz 타이머. Strength 100%의 시간 상수 0.35초. 마우스를 놓으면 커서까지 따라와 끝남(ZBrush처럼 지연
  위치에서 멈추는 옵션은 없음). Mask(숨김)에는 연결하지 않음.
- Deform: Falloff 거리는 직선(유클리드) 거리 — 굽은 Bend Curve에서는 곡선을 따라 잰 거리가 아님. Mecha 기즈모는 선택 중심에
  표시(Each Point 피벗일 때도 위치는 중심). Bend Curve Scale = 반지름(두께)만, 점 위치는 그대로. Lattice 해상도 변경은 Blender가
  기존 변형을 재샘플(B-Spline에서는 근사). Rigid Pose는 여전히 미구현.
- Mask는 숨김만 했습니다(코드·데이터 유지). 완전 삭제는 승인 후.


## A. 검증되지 않은 것 (가장 중요)
**Windows 11 + Blender 5.0.2 GUI에서 실행된 적이 없습니다.** 모든 자동 테스트는 Linux headless `bpy 5.0.1`입니다.
headless에는 창·실제 이벤트가 없으므로 아래는 **GUI 미검증**입니다:
- Workspace 생성(`workspace.duplicate`) 및 타이머 기반 왼쪽 영역 분할, 왼쪽 Properties(Tool 탭) 도구 목록 표시.
- Tool Header의 공통 Shape 팔레트 표시·클릭, 팝업(`wm.call_panel`) 위치·크기.
- 실제 이벤트 순서: Esc, 더블클릭(OS가 PRESS+DOUBLE_CLICK을 함께 보내는 경우 포함), 트리플 클릭 시간창(최대 0.72초,
  12px), RMB 단일/더블 타이밍, Free Draw 중 MOUSEMOVE 빈도, Lasso 드래그 그리기.
  → 상태기계 자체는 같은 클래스에 가짜 이벤트를 넣는 테스트(68개)로 검증했지만 GUI 이벤트 우선순위를 증명하지는 않습니다.
- WorkSpaceTool 키맵(LMB/RMB/Esc/Space)이 Object Mode 기본 키보다 우선하는지.
- Loft의 Live 갱신은 depsgraph 핸들러로 headless에서 동작 확인(커브 점/오브젝트 이동). GUI에서 편집 모드로 커브를 고칠 때의
  갱신 빈도/성능은 미측정.
- ZBrush: 실제 ZBrush가 없어 **ZBrush가 쓴 OBJ 파일로는 테스트하지 않았습니다**(파일 내용을 바꿔 ZBrush 수정을 흉내 냄).
  ZBrush의 OBJ 축/스케일 관례(위아래 뒤집힘 등)는 사용자 환경에서 Forward/Up/Scale로 맞춰야 할 수 있습니다.

## B. 구현됐지만 범위가 좁은 것 (부분 구현)
- **Base Mesh**: 뷰에 수직인 평면 위 독립 솔리드만. Surface Follow / Project(곡면을 따라 휘는 장갑판)는 미구현.
  Dome의 Edge Height는 최소 Height의 1% (0이면 닫힌 솔리드를 만들 수 없음). Dome 해상도 상한(내부 점 12,000개).
  Bevel/Chamfer 폭이 너무 크면 Blender bevel clamp로 줄어듦. 원근 뷰에서는 윤곽이 평면에 원근 투영됨(그 뷰에서 보면 일치).
- **Curve Lasso**: 핸들은 정렬된 대칭 핸들(좌우 길이/방향 독립 아님). 첫 점 클릭은 '닫기'라서 첫 점을 각진 점으로 바꾸려면
  다른 점을 먼저 찍은 뒤 조정해야 함. 급한 곡선은 자기교차할 수 있음(이때는 획을 유지하고 경고).
- **Loft/Surface**: 열린/닫힌 커브 혼합 불가. 각 커브의 첫 스플라인만 사용. 섹션 순서는 활성 커브부터 가까운 순서(또는 이름).
  연속성(G1/G2), 트리밍, 진짜 NURBS 패치 없음. Cap은 n-gon(비평면일 수 있음).
- **ZBrush Bridge**: OBJ만, GoZ 아님. 다시 가져오면 UV·셰이프 키·커스텀 속성은 OBJ에 담긴 것만 남음. 머티리얼은 슬롯 목록만 복사.
  OBJ 그룹이 여러 개면 하나의 메쉬로 합쳐 원래 오브젝트에 넣음(사용자 오브젝트끼리 Join하는 것은 아님).
- **Esc 동작 변경**: 이제 Esc는 항상 선택 도구로 돌아갑니다. 그리던 획만 지우고 도구에 남고 싶으면 Backspace/Ctrl+Z로 점을 지우세요.
- Mecha 도구 4개(Cut/Split/Mask/Base Mesh)는 모든 Workspace의 Object Mode T툴바에 보입니다(Blender 도구 등록이 전역).
  단축키(Space/B/C)는 MECHA LAB 탭에서만.
- 우클릭 선택(Right-Click Select) 키맵 사용자는 Mecha 도구 중 RMB가 선택 대신 팝업/종료로 동작.
- Mask: **면 단위**, Cut/Boolean 보호 없음, Weight/Pose 없음. Live Cut(Auto Apply OFF)에서는 Edge Finish 미적용.
  Smart Fuse는 실제로 겹친 닫힌 메쉬만.

## B-2. 0.9.0 기능의 범위
- Mesh Curve: Twist는 시작→끝 선형 누적(구간별 제어 없음). 경로에 기존 tilt가 있으면 더해짐. Rotation은 단면/복제본 기준.
  Edit Mode 점 더블클릭 키맵은 Blender의 다른 Curve 더블클릭 동작보다 먼저 받음(Mecha 경로가 아니면 통과) — GUI 미검증.
- SubD Plane: Crease는 선택 엣지에 값 쓰기만(전용 시각화 없음). Apply All은 Simple→CC→Solidify 순서만 적용하고 그 밖의
  사용자 모디파이어는 남김.
- Radial: Ring Rotation은 링 중심(3D 커서 위치에 놓인 캐리어 원점) 기준. 오브젝트 회전과 함께 쓰면 둘 다 적용됨.
- Gap Split: Gap Width는 대상 중심 깊이에서 화면 픽셀로 환산 → **직교 뷰에서는 정확, 원근 뷰에서는 깊이에 따라 약간 다름**.
  오목한 도형에서 Gap이 오목부보다 크면 거부. Live(Auto Apply OFF) 미지원.
- Split 양쪽 마감은 Cap Split ON일 때만(캡 면이 없으면 '새 엣지'가 없음).
